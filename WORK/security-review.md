## 範囲

`requirements.md` と `AGENTS.md` を基準に、HTTP アダプタ、D1 スキーマ・リポジトリ、Jev アダプタ、Domain Core、画面の文字列表示・成果物出力を確認しました。実 API、実ユーザーデータ、Cloudflare リモートリソースへの書き込みは使用していません。

## 指摘と修正確認

- SQLite の日付 CHECK で `date(...)` が NULL の場合に不正な月・日を受け入れていたため、NULL を明示的に拒否。投稿日・撮影日・工程締切の回帰テストで確認しました。
- Node の型除去モードが非対応の constructor parameter property を通常のフィールド初期化に変更。実装を import するテストが実行できることを確認しました。
- 台本ブロックの最大入力に対して JSON 上限が小さかったため 96 KiB に調整。6 ブロックに計 18,000 Unicode コードポイント（絵文字）を保存するテストで確認しました。
- 企画型・台本・撮影メモ・日程を更新した後に古い編集指示書が残る問題を、依存する成果物のセッション付き無効化で解消。再生成後の指示・秒数・納期と、無関係な案件が維持されることを確認しました。
- 月次の整数差分への不要な小数丸めによる誤差を修正。安全な整数範囲の大きな値について正確な差分を確認しました。
- 極小の前月維持率から変化率が無限大になる場合を、明示的な算出不能注記と null で表現。JSON に非有限値を出さないことを確認しました。

- API が任意の RangeError や名前だけを ValidationError にした例外の message を返す問題を修正。実際の DomainValidationError インスタンスだけを安全な入力エラーと判定し、他の例外は秘匿する回帰テストで確認しました。
- 遅延した保存応答が新しい画面の入力・フォーカスを上書きする問題を、画面世代による描画抑止で修正。古い企画保存応答が新しいメモのドラフトを消す経路も抑止し、画面を再往復して保持を確認しました。
- 複数の企画があると古い企画の再生成後に別企画を表示する問題を、ideaId による対象選択へ変更して確認しました。
- バックエンドの表示文言・Jev質問文をデータに分離しました。

## 独立テストの結果

`node --test test/security-review.test.ts`: 16 件成功。

- 異なる 2 セッションの読み取り・全更新経路・子エンティティ ID の混入を拒否
- 拒否された更新前後で保存済み成果物が不変
- レスポンス本文からセッション所有キーを除外し、no-store を付与
- 別オリジン送信、JSON 以外、配列・プリミティブ、不正 JSON、実バイト数超過を拒否
- 列挙・文字数・数値・実在日付・台本ブロック重複を検証
- ハニーポットに値がある場合、DB 操作前に破棄
- インフラ例外の内部情報をレスポンスに含めない
- 日次消去は所定 Cron のみで実施し、全テーブルにカスケード。古い Cookie は新しいセッションへ更新
- 変更後の派生成果物が古い内容を表示しない

## 設計上の確認

SQL は入力を bind し、通常の読み書き・無効化は session_id によって範囲を制限します。複合外部キーにより別セッションの関連付けも DB で拒否します。無条件の消去はスケジューラ専用の resetAll に限定されています。

画面は createElement / textContent / value で表示し、利用者の文字列を HTML として解釈する箇所は確認されませんでした。認証・計測・追加クラウド AI・暗黙の分類フォールバックは導入されていません。

## 未検証・公開前に確認する点

Jev の実通信は無効のままです。公式の Choice の confidence は候補 probability と異なるため、閾値には confidence を使用します。モデル応答のバージョン違いは失敗として扱います。これは応答検証であり、公式入力スキーマで非公開のバージョン指定を追加するものではありません。

現行の公式 Jev ページは第三者モデルとトークン料金を表示し、Workers AI の価格表から Jev が 10,000 Neurons の無料枠に含まれるとは確認できません。有効化前に実アカウントで提供条件・課金条件を確認する必要があります。環境変数 WORKERS_PLAN の文字列だけで実際の契約・課金状態を保証しません。
