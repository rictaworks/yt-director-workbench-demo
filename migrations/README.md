# D1 マイグレーション

`0001_initial.sql` は `requirements.md` の ER 図に対応する11テーブルを作成します。

- 全テーブルに `session_id` を保持します。
- `(session_id, 親ID)` の複合外部キーで、異なるセッション間の関連付けを DB 層でも拒否します。
- 1案件1チャンネル、1企画1企画シート、1企画シート1台本・スケジュール・編集指示書、1案件1月の実績は UNIQUE 制約で保証します。
- 入力列挙値、整数・範囲、実在日付、JSON 形式に CHECK 制約を設けます。
- 台本や指示書などの生成結果は必須 ER 列に加え `payload_json` に保存します。ID・所有者・関連ID・編集可能な工程やメモは正規化した列を正とします。
- セッションを削除すると関連データがすべて CASCADE 削除されます。全件削除は JST 03:00 の Cron 専用です。
- 通常の読み書きは `src/backend/repository.ts` 経由とし、セッションIDと親案件の所有を検証します。

`test/repository*.test.ts` は Node 24 の SQLite で実際の SQL とリポジトリを実行し、制約、トランザクション、保存復元、セッション間の読み書き分離を検証します。

ローカルの起動・適用手順は `README.md` を参照してください。リモート DB の作成・マイグレーション適用は別途承認が必要です。
