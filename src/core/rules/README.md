# 決定的なルール

- 入出力はJSTの暦日 `YYYY-MM-DD`。現在日はアダプタが `Clock` または引数から与えます。Coreは時刻・ネットワーク・DBを取得しません。
- 曜日計算にはUTC上の同じ暦日を使用します。営業日は月〜金で、祝日は除外しません。実際のタイムゾーンやDSTには依存しません。
- 各工程の標準日数は直前の工程締切から当該工程締切までの間隔です。最初の企画確定締切を今日に置けるため、最短投稿日は次営業日以降の企画確定から9営業日後です。今日が平日なら企画確定を今日にできます。
- 固定撮影日は維持し、前工程は撮影から逆算、後工程は投稿から逆算します。後工程の必要6営業日に満たない場合は利用可能な営業日を比率配分し、圧縮警告を返します。0営業日の工程も明示的な圧縮として扱います。
- 固定撮影日に準備が間に合わないときは日程不足と撮影日の見直しを示し、最短撮影日・投稿日を提案します。入力された固定撮影日を黙って変更しません。
- メモは仕様内の下限の矛盾を解消し、例外条件に合わせて空白以外の2〜500文字とします。尺はショートを利用可能にするため1〜1800秒（既定480秒）です。60秒未満は3ブロックです。0秒ブロックが生じる極短尺には警告を返します。
- 秒数は各ブロックを切り捨て、余りを本論へ配分します。前月比は差分と百分率、維持率の差分はパーセントポイントです。率表示は原則小数点以下2桁に丸めます。極端な値で計算可能範囲を超える率は欠損と明示します。
